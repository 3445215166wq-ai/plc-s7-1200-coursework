## 题目类型

「基于**顺序控制**」，也就是要求用顺序功能图的思路做交通灯：把整条灯序拆成一个个步，
每步点亮一组灯，由一个定时器到点作为「转换」条件进入下一步。不用顺序功能图也能硬写出来，
但题目点名要顺序控制，考的就是这个组织方式。

## 时序推出来的互锁关系

把块名的时间加起来正好对上：

```
南北绿灯 15s + 绿闪 3s + 黄闪 2s = 20s  ←→  东西红灯 20s
东西绿灯 15s + 绿闪 3s + 黄灯 2s = 20s  ←→  南北红灯 20s
```

也就是说**一个方向走完「绿→绿闪→黄」刚好 20 秒，另一方向这时正好是 20 秒红灯**，
两方向的绿灯时段完全不重叠——这是交通灯最核心的互锁：一方绿时另一方必须是红。
整条灯序一轮 40 秒。

红末尾的 3 s 闪烁是两个方向都做了的，作用是红灯结束前先闪，提示「马上要变绿」。

## 实现要点

- 每一步用一个置位位 + 一个定时器：定时器到点 → 复位当前步、置位下一步，
  这就是顺序功能图里「转换」的写法。
- 闪烁不是写一堆交替触点，而是用一个较小周期的定时器产生方波，再和「当前灯步」做与运算，
  所以「绿闪 3 s」「黄闪 2 s」只是换了个时间参数，逻辑是同一份。
- 启动 / 停止作为整条步序的总闸，停止时把当前步和所有定时器一起清零，再从第一步重新开始。
